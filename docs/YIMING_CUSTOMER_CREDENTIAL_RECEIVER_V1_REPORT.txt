2. PRIVATE_ANONYMOUS_PIPE_V1 的实际衔接

launch 创建两条独立 O_CLOEXEC 匿名 pipe，分别为凭据与 ACK，FD>2，不使用标准输出传密码。
独立 receive 子进程持有凭据读端与 ACK 写端；69696 producer 持有反向端。
原 handoff_ready() 检查实际 /proc PID/UID/exe/cmdline SHA、匿名 pipe inode 与方向。
Receiver 不重写或降低上述检查。Receiver 返回的绑定字段严格为：
mechanism,receiver_pid,receiver_uid,receiver_executable_sha256,receiver_cmdline_sha256。

本候选是 Python 程序，不是假称 native compiled binary。
/proc/exe Hash 单独只能绑定 Python；因此同时强制 -I -B、Root-owned 受保护代码及
完整父路径、命令行内 receiver code SHA、Root-owned 解释器及 cryptography 模块。
拒绝用户 site/PYTHONPATH/PYTHONHOME/LD_PRELOAD/LD_LIBRARY_PATH 注入与可写/软链接代码。
程序以批准的非Root UID执行，不给该用户 Root 安装权限。
须由独立审批人把 Receiver Git 身份、代码 Hash、解释器/依赖 Hash、路径与公钥指纹
纳入受保护安装证据；原四项 Tooling code_pins 不增加字段，也不改成 Receiver Source。

只接收四项字段 operation_id/tenant_id/admin_email/temporary_password，拒绝重复字段、
错误固定身份、额外字段、多帧、超长/非完整帧及不符合原 secrets.token_urlsafe(32) 的密码。
采用负责人批准的 RSA3072 或 RSA4096 公钥，SHA256 指纹定义为 DER SubjectPublicKeyInfo。
RSA-OAEP SHA256 / MGF1 SHA256 加密整个原始凭据包（包括结尾 LF）。
固定包小于 OAEP 上限；超限拒绝，不静默截断或换算法。
参考官方协议 API：https://cryptography.io/en/latest/hazmat/primitives/asymmetric/rsa/
及 https://docs.openssl.org/3.0/man3/EVP_PKEY_encrypt/ 。

密文写到 operation.pending.rsa-oaep-sha256.bin：0700 私有目录、0600 文件、
O_EXCL/O_NOFOLLOW、文件 fsync 与目录 fsync。名称中的 operation 为上述准确完整 UUID。
失败保留非敏感 claim/待核对密文，不自动覆盖、删除或再次提交。
只在安全持久化完成后写一次 ACK：
{"operation_id":"9af042d7-04c0-4253-9ee6-5bb429e81456","credential_sha256":"SHA256(raw_packet_including_LF)"}
原 producer 保持 2秒写等待、5秒 ACK 等待及精确 JSON 相等校验。
不输出 payload/临时密码/Key到 stdout、stderr、argv、环境、日志、Git或普通文件。
Core dump=0；明文仅短暂位于进程内存，不承诺 CPython 可证明的完全内存擦除。
本轮没有生成客户密钥或导出私钥；隔离测试使用临时合成测试私钥，仅在测试进程内。

3. Commit 门禁与一次性执行

ACK != 数据库 Commit != 客户登录。密文始终为 PENDING。
launch 默认仅 dry-run；execute 模式也先运行正式 --dry-run，要求 execution_ready=true，
7 INSERT/0 UPDATE/0 DELETE，然后必须在本人终端输入准确 EXECUTE <operation_id>。
同一 Receiver PID 和不可变 Approval 跨越 dry-run/execute，避免更换 PID 后复用旧审批。
单独 dry-run 后结束的 Receiver PID 不可复用；如正式 Authority 已签发又撤销，须重新审批，
不能改写旧 Approval 或重新启用已撤销权限。
等待签发最多300秒、Receiver窗口最多600秒、明确确认最多60秒，原审批最长24小时。
原 producer 执行 Serializable 事务、写 INTENT、核对数据与权限、交付 pipe、检查 ACK、
COMMIT 后写 COMMITTED receipt。launch 只接受 producer 成功与该 Operation 的 COMMITTED。
仍要求独立只读核对 DB 中精确 Tenant/Admin/余额/实例及 Receipt，然后才能领取密文。
Receiver 从不自动解密、交付客户或做业务 SQL。
提交异常、NOT_CONFIRMED、COMMITTED_RECEIPT_PENDING 均停止并隔离待核对密文；不自动重试。
