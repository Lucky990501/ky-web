7. Operation and recovery semantics

PREPARED -> QUIESCING (durable BEFORE stopping) -> QUIESCED
 -> SWITCHING -> SELECTED -> COMPLETE.
Recovery records RECOVERING -> RECOVERED, with durable retries.
Source pointer + approval + three profiles are not one filesystem atomic rename.
Safety is quiescence, serialized durable intent, restart gating and deterministic
recovery. No service starts until actual selected Loader passes. Unknown approval,
pointer, authority or history rejects. Repeated terminal calls reverify exact pair.

prepare: full predecessor identity/data compatibility; old byte SHA; independent
target issuance and immutable archives; no active approval change.
activate: quiesce all three services, predecessor guard, readonly full schema/data
fingerprint, durable switching intent, select approval + source + profiles,
real Loader, compatible startup through existing operator, health and pair check.

Recovery branch A (no new persisted changes):
  exact baseline equality AND original predecessor Guard predicates must pass.
  Only then select original d8a bytes/source/profile; real Loader; old Guard/health.
  Missing/invalid predecessor compatibility never becomes a permissive fallback.
Recovery branch B (ANY persisted schema/row change):
  never downgrade. Select exact28e + its approval/profile; call the existing
  runtime_recovery_operator.py recover. It preserves Admission, reconciles Admin,
  verifies compatible Native Guard and checks config unchanged. Then recheck
  Loader, source/approval, compatible Native status and health.
  Unknown/invalid data still rejects in the existing Guard. Forward is not a pass.
  A recorded forward direction cannot later downgrade; conflicting old-direction
  retry data rejects. No database restore/delete or quality PASS fabrication.

The operation fingerprint is a conservative temporary equality check of existing
readonly collector schema + all rows, not a new fixture pin/witness authorization.
No secret value is stored in the receipt or command output. Collector identity,
base Guard/policy pins and exact DB target are checked before snapshot access.
Persisted changes unrelated to Runtime Tests also force forward (conservative).
