2. What is implemented

scripts/test_delivery_pipeline.py:
- package: exact committed Source/Tree -> unchanged builder -> original
  Manifest -> independent full Git-byte/file-mode/package readback.
- verify: deny extra/duplicate/link/traversal members, mismatched Source/Tree,
  Archive/Manifest/hash, or unrecognized static transformation.
- plan: candidate identity, Git parents and actual observed runtime predecessor
  are separate fields. No77e/e70/894/B1 constant in the reusable implementation.
  Real execution re-observes PRIMARY; an input snapshot is NOT a live proof.
- execute: fail-closed isolated qualification consumer. Requires installed
  Root-owned policy, exact request-bound single-use grant, complete Tooling pins,
  runtime/driver pins, qualified Linux profile receipt and protected paths.
  It does not issue grants or install itself. The only adopted action currently
  supported is isolated_qualify, NOT PRIMARY activation or Production release.
- Exact Operation gets an exclusive attempted record; unknown/failed attempts
  are retained, never overwritten or automatically retried.
- A trusted nonblocking qualification lock serializes these bounded isolated
  runs; it does not take over or alter the existing PRIMARY release lock.
- Approved driver runs non-Root, private network, protected host paths,
  restricted cgroup, bounded tmpfs and bounded stdout. No inherited credentials.
  Revocation/expiry and host disk floor are checked during the run.
- Complete qualification results must name real PG/Redis/Worker/MCP, source,
  operation, all required tests, actual disk metrics and zero external calls.
  Missing tests, SQLite results, paid calls or isolation changes reject PASS.

scripts/test_delivery_verified_entry.py:
- Root bootstrap using isolated Python. Pins the whole adopted Tooling tree
  BEFORE importing the delivery code. Rejects additional files, bytecode, links,
  writable/ACL-unreviewed ancestors and interpreter mismatch.
- Direct Root import/execution of the ordinary delivery module refuses before
  importing project modules. Non-Root local package/plan commands remain usable.

build or Native proof. Production promotion must reuse the exact archive and
Manifest already qualified on Linux, not rebuild different bytes after testing.

The policy supplies actual approved paths and identities, not caller argv:
environment=test; hostname; primary_pointer; release_root; source_repository;
operations_root; tooling_root and complete tooling_files; runtime_root;
python/python_sha256; qualification_driver/driver_sha256;
driver_protocol=QUALIFICATION_DRIVER_PROTOCOL_V1; operator_uid/operator_gid;

native_adoption_receipt and its SHA256.

The independently granted per-run record binds action=isolated_qualify,
canonical request/policy SHA256, exact operation_id, real not_before/expires_at
(maximum4hours), uses=1, revoked=false, and actual issuer_record. This interface
is NOT an issuer and does not certify an Owner chat message as a machine grant.
No concrete policy, approval, UID, approval timestamps or Linux receipt has
been created by this candidate.

The driver consumes /input/request.json, candidate archive/manifest and the
independently verified exact predecessor archive/manifest. It uses the bounded
/private/tmp tmpfs for ALL PG/WAL/temp/Redis/fixtures/cache/
logs, extract only the verified artifact, start real processes from that
artifact, and emit one bounded sanitized JSON result. No key or real customer
record is mounted. OperatorUID must differ from all protected service UIDs to
avoid same-UID /proc environment access. A separate test account requires the
existing explicit installation/adoption permission; it is not auto-created.

Disk: 704MiB tmpfs scratch + <=63MiB COMBINED read-only inputs + <=1MiB receipt <=768MiB;
additional256MiB host reserve. No clearing cache, 20% threshold change or cloud
purchase. tmpfs is memory-charged and swap is disabled for the isolated job.
This is a proposed enforceable layout, NOT a measured startup/peak result.
Native adoption must prove mount ordering, runtime relocation/imports, host
socket/proc isolation, ENOSPC behavior, cgroup cleanup, zero egress and evidence
retention. A mock sandbox argv test does not prove these Linux facts.

6. Recovery and PRIMARY status

The plan compares exact migration file identities, but explicitly leaves
primary_recovery_ready=false. No schema equality can establish compatibility
of newly written Task/Run/Conversation data by itself. Qualification must read
new fixture data with the predecessor, and the existing backup/recovery entry
must have an applicable approved binding before any PRIMARY cutover.

No PRIMARY switch or PRIMARY DB restore is implemented by this candidate. Primary
activation remains a separate not-yet-closed adapter to existing Release tools,
not a shell shortcut. A failure in the isolated job stops only that exact unit,
keeps input/attempt/failure receipts, and does not touch894 or restore a database.
The new driver restores only its own synthetic dump into a new private DB,
compares all public table row fingerprints and exercises the predecessor's real
ProductStore read path without initialize or migration. This is isolated backup
and old-reader compatibility, NOT PRIMARY service rollback or Production safety.
Migration bytes must match; a different migration set stops without inventing a
new migration contract. Existing Production recovery tooling remains unchanged.

Tmpfs scratch is ephemeral; full failed PG state is NOT retained after teardown.
Only bounded sanitized results/stage labels and immutable inputs survive. If a concrete
test requires full failed-cluster retention, it needs a reviewed bounded store
instead of silently exceeding the current budget.
