# Ordinary Release V1 — implementation candidate, not Production enablement

Baseline: actual deployed `d9063ee43bc65e821457221ad824f5dde84fe408`.
Design: 01 thread `01a0af20-ce3a-7e81-8ad7-666f4adee982`, accepted user

neither the current V2/V3 consumers nor any application/Skill/migration bytes.

## Implemented bounded path

1. Existing builder produces an exact Git archive and existing base Manifest.
   Prepare a Git bundle and immutable plan; normal package code is unchanged.
2. Owner posts one exact approval of the plan hash and Operation on the
   existing repository issue. No pre-known comment ID is embedded in its own
   hash. Broker independently GETs the event, exact numeric author identity,
   login, issue, full body and unedited timestamps; zero/multiple events reject.
3. Client sends one framed JSON envelope over a **restricted non-Root SSH
   identity**. Fixed `authorized_keys` forced command invokes only the broker
   `rpc` entry through an exact sudoers rule. No shell, arbitrary commands,
   destination paths, sources, SSH TTY, environment changes or retries.
4. Before first write: exact adopted machine grant, Owner event, all 18 report
   bytes/identities/time/attribution, archive/Manifest/member checks. Exclusive
   Operation directory preserves partial receipt or input state. A lost reply
   means query this same Operation, NOT another submit.
5. Import only the hash-bound Git bundle using existing Git with hooks disabled;
   verify exact Source/Tree, full archive allowlist, each Git blob/mode and the
   existing static cache substitution. No candidate program is executed.
6. One fixed systemd job runs independently of the SSH client. Install outside
   the global lock; Root immutable complete readback. Inside the **same legacy
   global lock file**, freshly check actual predecessor, Owner, revocation,
   Schema015 ledger, backup, current service identity and recovery reserve.
7. Reuse the existing service configuration layout, fixed API/MCP/Worker argv,
   `release_verify.service_state/health`, and read-only
   `schema_015_runtime_only.ledger_snapshot`. Atomically switch the pointer;
   no Nginx change, Schema migration, Registry mutation, business task Smoke
   or DB restore. Full legacy `release_switch.sh` is intentionally **not called**:
   it still requires V3's exact-562 contract and fixed paid Smoke. Its existing
   protected entry remains fail-closed and unaffected.
8. Failure after activation attempts **one** exact predecessor recovery under
   the same lock, only if separate recovery scope/time/revocation, byte
   equivalence and current ledger allow it. Never rewind the database or delete
   valid new Task/Run/credit data. Audit events are exclusive, fsynced and chained.
9. SIGTERM enters the same guarded failure path. SIGKILL leaves an explicit
   incomplete intent; fixed systemd `ExecStopPost` may recover the **same**
   Operation once, within its recovery grant. A pending RESTORING or unknown
   pointer refuses automatic action. No `Restart=always`, second publication
   or mutation hidden behind a status query.

## First fast lane scope (deliberately conservative)

Only `enterprise_agent_poc/app/static/**` byte differences with exact declared
diff and non-executable modes are admitted. Every nonstatic packaged byte and
Git mode must match the current predecessor, including dependencies,
migrations, Skills, auth, Task/Run, credit and Tooling contracts.

Pure backend bugs cannot yet be automatically proven ordinary by this
classifier: they remain on the existing special release workflow, not silently
approved. Prompt Revision changes retain the existing Runtime Test / Publish
contract; this broker does not invent a second prompt deployment API.
This limits the first implementation's claim; it is not all ordinary changes.

## R1–R4 security successor to immutable 90d38ab

- Recovery rechecks the SAME authority after slow preflight, after durable
  RESTORING intent, before each actual service/pointer mutation, and before
  certifying RESTORED. Forward activation uses the same existing guard hook.
- Exclusive writes prepare/fsync hidden bytes before publishing a hard link;
  the directory is synced while the object still has two links. A single-link
  final record is therefore backed by already synced data/name. Interrupted
  transients remain evidence; unconfirmed chains report UNKNOWN, never success.
  Successful transient unlink is not history cleanup. All final drop-in/pointer
  replaces sync their parent directories. COMMIT_PREPARED is query/reconcile
  only, not a final successful publication.
- Direct Linux Python entry now refuses before importing any repository module.
  RPC and systemd both use the source-only entry with system Python -I -B -S,
  independent manifest digest and independently verified entry bytes. It reuses
  the unchanged V3 protected-source loader primitives after complete Tooling
  SHA/Git/permission capture. Repository/runtime imports use captured raw
  sources; candidate .pyc/.pyo and unpinned runtime modules are rejected.
  INSTALL_BOUND_MANIFEST_SHA256_REQUIRED is intentionally non-executable: only
  separately approved installation may replace it with a real approved digest.
  The formal manifest also requires the actual approved runtime closure; no
  off-line temporary/runtime hash is represented as a Production pin.
- The selected ciphertext must match BOTH the aggregate and independent
  protected restore proof, its exact proof SHA, Schema015, full database scope,
  source/restore environment IDs, captured/restored times and validity. Both
  proofs remain in the independent Root report store; the client cannot issue
  qualifications or substitute another ciphertext's proof. No database rewind.

The producer fixture used by the original backup-positive/negative tests gains
these required fields; assertions are unchanged. Original 01 probes/reports
are retained separately. Other test names are not removed or relabelled.

## Acceptance and remaining hard gates

### R1 post-Owner-query freshness successor

Within the existing global release lock and per-mutation guard, authorization
checks the protected grant both before and after the potentially slow Owner
GET. The post-GET check follows Owner identity/exact-plan validation and reads
the same trusted grant again, then checks the current window and machine/
operation revocation markers. No network request follows that final check.
Recovery/activation semantics, Operation journals and UNKNOWN handling do not
change. The two original 01 race assertions are retained without weakening.

This closes revocation **during** the Owner lookup, not arbitrary concurrent
Root writes after the final check. A separate writer that ignores the existing
global lock could still revoke between the last filesystem check and a syscall;
the controller cannot atomically combine an external marker write, a clock and
an os.replace. Actual revocation-writer/shared-lock interaction remains a real
06 acceptance condition, not a component-test PASS or a new emergency waiver.

Local tests exercise real child exit, local files, Git import, Linux flock,
SIGKILL, durable UNKNOWN state, exact recovery and valid new data preservation.
RPC/systemd/GitHub behavior in these tests uses labelled isolated substitutes;
it is **not** real Production systemd / PG / SSH / GitHub qualification.

Before any pilot: independent code/security QA, exact policy and restricted
Tooling installation approval, real Root installation/readback, valid Test
report provenance (including the protected report-store binding), backup/recovery,
and startup probe budget. The adapter for the real approved report producer is
NOT installed or proven here; the missing protected copies fail closed.

Before ENABLED: three **different and consecutive real Production** ordinary
versions, one Owner decision each, no manual deployment steps, actual service
health and immutable receipts, ≤15 minutes excluding full test/build, and at
least one real exact-pair restoration rehearsal. Each is a separately approved
pilot plan. Root-protected hashes of those actual receipts are independently
read before enablement; fixture cycles cannot satisfy the gate. Final formal
enablement authorization is separate. These cycles are NOT_EXECUTED today.

Current deployed d9063ee and its finite 562 recovery approval are unaffected;
neither grant is reused to install or enable this candidate.
