# 公众号文章写作与排版

写完整文章时提供三个与正文事实一致的标题候选，再给导语、自然小标题、正文、结尾和适合场景的CTA。用户只要求排版时保留原文文字、事实和顺序；不把参考文章的主题、人物或句子移植到本文。

## 事实与阅读体验

可以创作观点、结构、比喻与建议，不能虚构具体事实。用户材料没有提供的日期、地点、人数、金额、客户名称、现场行为、案例经过、效果数据、产品已有功能或未来安排不得补写为事实。非关键缺口直接省略，影响文章成立的关键缺口少量使用【待确认】。不附事实审计报告、写作过程或免责声明。

观点和知识类文章正常发挥，不必成为资料摘抄。以清晰导语、通常2～5个自然小标题和手机友好的短段落组织，不机械使用“首先、其次、最后”，不空泛排比或过度营销。只在需要企业事实或真实素材时查询对应工具，同一事实不反复检索。

## 已有排版规则

采用 [references/style.json](references/style.json) 的参数；来源是既有 wechat-html-draft 的 style.md 与 article-template.html，不另造通用蓝色模板。白底单栏，正文深灰 #3E3E3E、16px、行高1.6、字距0.544px；字体栈为 Optima-Regular、PingFangTC-light、PingFang SC、Microsoft YaHei、sans-serif。暖黄 #FFCA00 只用于少量重点和线条，正文段距从18px起，章节留白28～38px，引用和行动区使用浅底与暖黄边线。图注12px、灰色 #A0A0A0、居中。

正文使用常规Markdown表达语义：标题、小标题、段落、重点、引用、列表及合法图片引用。平台根据上述参数确定性生成内联样式HTML，正文根节点为 #article。不要再生成另一套CSS，不把HTML放入代码围栏，不声称字体、微信过滤或图片效果已通过真实编辑器验收。

图片仅使用当前用户已提供且有权读取的真实资料。不生成空src、未知本地路径、临时占位图片或未经授权的封面。没有图片时省略图片节点。复杂拼贴与手写效果属于后续独立图片任务，不用CSS冒充。

本Skill不自动上传草稿、发布或群发。需要草稿箱写入时必须走另行授权的既有正式接口；文章排版成功不等于草稿创建成功。
