# 微信公众号长文写作

## 何时使用

用户要一篇微信公众号完整文章、长文选题及成稿、活动报道或预热、企业案例、行业观点、知识科普、课程培训、品牌故事或产品服务介绍时使用。只要一句短文案、几个标题或社媒广告时，不机械扩写成长文；短营销文案交给相应的文案 Skill。

## 写作流程

1. 从用户输入、上传材料和已取得的企业资料中提取主题、读者、用途、品牌语气、可核实事实与缺口。简单需求也可以直接起草，不要求用户先填表。
2. 判断文章类型和阅读动线：活动报道重真实经过，预热重参与理由与行动方式，案例重背景—行动—可证实结果，观点重论点与论据，科普重读者问题与解释，课程和产品介绍重真实内容与适用对象，品牌故事重可信细节。不要把这些类型套进同一模板。
3. 先拟与正文一致的标题。完整文章可给三个简洁候选，再直接给可使用的正文；用户只要一个标题时只给一个。不得标题党、虚假承诺或暗示无依据的成果。
4. 正文用有信息量的导语开篇、通常 2–5 个自然章节与收束段组织；依内容增减，不机械写“首先／其次／最后”。每段适合手机阅读，小标题清晰，留白适度，少用空泛排比、列表和加粗。已知材料很少时写短而完整的文章，不靠虚构细节凑篇幅。需要行动引导时给简洁 CTA；没有真实报名渠道时不编造链接或联系方式。
5. 交付默认使用 Markdown 友好文本，不输出写作思路、结构分析、AI 自述或 HTML（除非用户明确要求）。

## 材料与表达

文章应以用户提供的资料和已取得的可信企业信息为依据。对真实活动、案例、品牌和产品，材料中的具体信息是封闭的事实清单；常见场景和合理推测不能补成这次事件的过程、人物言行或结果，也不能补成产品现有功能或企业未来承诺。不要把机构或群体换成材料没有指明的具体岗位或个人。

材料少时，先准确交代已知事实，再用通用解释、观点、比喻或明确的建议组织后文：

- 案例缺少过程时，讨论相关问题和可尝试的方法，不为该案例续写经历。
- 产品只有定位时，介绍定位，再谈该品类的用途和选用标准，不声称这款产品具备未经提供的功能、机理或效果。
- 活动只有主题时，写主题倡议，不声称主办方已安排环节或会发布、开放报名；关键活动信息如需对外说明，可简短标【待确认】。

可以创作观点，不能虚构具体事实。非关键缺口直接省略。标题不能超出正文依据；结尾不附资料缺口说明或免责声明。

只有文章确实需要企业事实时才查询企业配置或知识；仅在用户需要真实企业图片、Logo 或历史素材时查询素材。避免为同一事实重复检索，不声称不存在或未找到的资源已可用。

## 交付检查

交付前核对：文章是否完整而非短广告；标题是否与正文一致；每个具体事实是否有依据；未知详情是否被省略或就地标记；段落是否自然、易读；CTA 是否有真实可用的参与路径。只输出文章本身，不附“使用说明”“发布前删除”“交付前自查”“本文未虚构”等写作过程或免责尾注。避免机械总结、夸张营销及无内容的品牌口号。
